# PaperPilot 产品体验优化 · 目标设定

> 版本 v1.1 · 2026-08-17 · 作者提出诉求，AI 协作起草
> 用途：为「持续优化整个产品」设定方向、边界与验收标准；同时作为《项目管理》课程作业中"目标管理"实践素材（SMART 目标 + OKR 关键结果）。
> v1.1 变更（作者当日修订）：功能范围开放——允许新增功能模块（须提案评审）；允许功能板块级重构（视觉基调不变）。原 v1.0 "MoSCoW 冻结、不加新功能" 边界相应放宽。

## 一、背景与问题定义

功能层面已交付（Sprint 1+2 完成：选题/写作/文献/计划四模块 + 论文主页 + 设置，G4 两轮反馈迭代至 v2.10），视觉体系 v3.0「纸墨朱砂」已完成。但作者真机体验后的判断是：**功能都在，用起来不顺手，不成熟。**

问题本质不是缺功能，而是「功能可用」与「体验成熟」之间的差距：

- 知道有什么功能，但不知道"现在该做什么、做完去哪"
- 操作有结果，但反馈不完整、状态不可见
- 部分交互仍是"表单 + 结果框"的工具感，不像一个连贯的产品
- 边界场景（空态、错误、中断恢复）打磨不足

## 二、产品愿景

让一个在职研究生在任何碎片时间打开 PaperPilot，都能**不假思索地推进论文一步，离开时清楚知道下一步做什么**。

## 三、优化目标（Goal）

**截至 2026-09-05（G5 交付验收），PaperPilot 达到"成熟产品"体验标准：新用户 10 分钟内独立完成首次写作闭环；核心旅程全程无卡点；全模块零崩溃零报错；桌面与移动端体验一致可用。**

对"成熟产品"的操作性定义（验收时逐条对照）：

1. 新用户不看任何说明，能独立完成核心旅程
2. 用户在任意页面、任意状态下，都知道"下一步做什么"
3. 每一次点击都有反馈；每一个等待都有进度；每一个完成都有标记
4. 每一个错误都有中文解释和出路；每一个空状态都是行动的邀请
5. 数据之间的衔接在界面上可见、可点、可回

## 四、关键结果（KRs）

| # | 关键结果 | 衡量标准 |
|---|---|---|
| KR1 | 首次闭环 ≤ 10 分钟 | 新用户从打开页面到完成「定题 → 采用大纲 → 写第一段 → AI 润色 → 插入引用 → 打卡」≤ 10 分钟，全程无需指点 |
| KR2 | 核心任务完成率 100% | 5 个典型任务（首次配置、选题采用、按章写作、文献入库并引用、生成计划并打卡）在可用性走查中一次性完成，无"不知道该点哪里"的卡点 |
| KR3 | 体验缺陷清零 | 走查清单（衔接可见性 / 状态反馈 / 空态引导 / 错误提示 / 防误操作 / 中断恢复）发现缺陷全部修复，P0/P1 零残留 |
| KR4 | 零崩溃零报错 | 全模块自动化回归零控制台错误、零渲染失败；6 视图 × 桌面/移动端零横向溢出 |
| KR5 | 移动端可用 | 390px 宽度下核心旅程（写作、打卡）可完成，导航/编辑器/甘特图不破版 |
| KR6 | 反馈闭环 | 每个用户动作都有可见反馈（按钮态 / 结果框 / toast / 印章标记），AI 生成有进度态，不存在"点了没反应" |

## 五、非目标与边界（v1.1 修订）

- 不引入后端、账号、云同步（纯静态 BYOK 架构不变）
- 合规红线不动：不做整篇代写、不做 AIGC 检测
- 视觉基调不变：v3.0「纸墨朱砂」体系保持统一；单个功能板块的布局与交互模型支持重构（作者明确）
- 新功能模块：开放（作者明确），须符合产品定位、用户价值明确；每个新功能先提一句话方案（解决什么问题 + 入口在哪 + 工作量估计），作者拍板后实施——MoSCoW 基线冻结调整为"基线冻结 + 变更评审"，防范围蔓延

## 六、设计准则（从既往 7 轮反馈提炼）

1. **衔接可见可点**——任何数据层衔接必须有界面层入口与去向
2. **编辑器优先**——AI 动作作用于选中文字，消灭"表单+结果框"工具感
3. **一次到位**——批量 + 审核优于逐项操作
4. **可解释**——AI 输出带理由/出处，用户能判断
5. **按使用时机切分**——在"用"的地方给工具，不在"管"的地方堆功能
6. **点必有应**——点击有反馈、等待有进度、完成有标记
7. **空态即邀请**——每个空状态都给下一步行动按钮

## 七、衡量方法与工具

- **可用性走查**：以核心画像（在职非全研究生，时间稀缺）的旅程逐页走查，缺陷分 P0（卡死旅程）/ P1（明显别扭）/ P2（锦上添花）
- **自动化回归**：Playwright 断言套件（现 60+ 项），随每轮修复持续扩充
- **真机验收**：作者本人按 KR1/KR2 计时实测
- **记录载体**：report/dev-log.md（每轮记录"人提的问题 → AI 的改动 → 人的评价"）+ PRD 变更记录
