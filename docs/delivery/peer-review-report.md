# PaperPilot 同行评审方案与记录

## 1. 评审目标

评审目标是验证 PaperPilot 是否能够稳定完成论文写作辅助的核心流程，并检查安全、伦理、可用性和上线交付质量。评审依据包括 PRD、测试用例清单、安全测试说明、伦理合规说明和线上系统。

## 2. 评审范围

| 范围 | 检查内容 |
| --- | --- |
| 产品流程 | 项目创建、研究设计、写作台、文献与证据、导出与设置 |
| 可用性 | 页面信息层级、按钮文案、卡片排版、流程跳转和错误提示 |
| AI 能力 | 模拟模式、真实 API 调用、加载状态、失败提示、使用留痕 |
| 数据安全 | 本地存储、API Key 可见性、备份恢复、清除数据 |
| 学术伦理 | 是否避免代写、是否披露 AI 使用、是否保留引用和证据链 |
| 上线质量 | GitHub Pages 页面展示、资源路径、构建产物和访问稳定性 |

## 3. 评审方法

采用“任务驱动 + 检查表”的方式：

1. 使用线上地址打开系统，新建论文项目。
2. 按研究设计问卷完成题目、方案和大纲生成。
3. 在写作台生成一段章节初稿，检查流式输出、引用插入和文献库同步。
4. 使用学术润色、补充论证、重构表达、续写和逻辑检查工具。
5. 执行导出前检查，导出 Word、PDF、Markdown。
6. 查看设置页的数据备份、安全说明和 AI 使用声明。

## 4. 当前评审结论

| 评审项 | 结果 | 说明 |
| --- | --- | --- |
| 核心流程 | 通过 | 从项目创建到研究设计、大纲、写作、文献、导出可以形成闭环 |
| 可用性 | 通过 | 主要页面已完成多轮 UI/UX 调整，写作台和文献页核心操作已收拢 |

| 数据安全 | 通过 | 数据保存在本地浏览器，AI 调用前做不可信输入隔离 |
| 学术伦理 | 通过 | 不提供整篇代写入口，导出物包含 AI 辅助使用声明 |
| 上线访问 | 通过 | GitHub Pages 可访问，静态资源路径已修复 |

## 6. 已采纳的评审类修改

- 将研究设计改为问卷式流程，降低一次性展示的信息量。
- 写作台支持目录折叠、章节定位、生成初稿流式输出、AI 建议回写和导出前检查。
- 文献与证据页收拢为文献检索、文献库和证据卡列表。
- 设置页隐藏演示入口和真实 AI 调用开关，保留高级设置入口。
- 加入提示词注入防护、AI 使用记录和导出声明。
