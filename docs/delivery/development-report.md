## 1. 项目概述

PaperPilot 是一个面向学生论文写作场景的轻量级辅助系统，目标是覆盖从“确定选题、形成研究设计、生成大纲、按章写作、管理文献、整理引用、计划推进、模板预览与导出”的完整论文工作流。

项目坚持三个核心原则：

- **全流程辅助**：不只做单点润色，而是把选题、写作、文献和进度串成一条主线。
- **学术诚信优先**：AI 只做辅助，不替代用户完成论文；所有 AI 生成内容都要求用户自行审校。
- **低门槛交付**：纯前端部署，用户自带 API Key，数据保存在本地浏览器，适合课程展示、个人试用和内测。

## 2. 产品分析与需求来源

项目最初从论文写作痛点出发，经过市场与用户调研后，确定核心痛点包括：

- 选题与开题阶段缺少可行性判断。
- 大纲组织困难，章节之间缺少逻辑主线。
- 文献检索、引用和 GB/T 7714 格式整理耗时。
- 写作过程中需要润色、补充论证、续写和结构检查。
- 论文周期长，容易拖延，缺少计划与进度反馈。
- AI 使用存在学术诚信风险，需要清晰边界和提示。

基于上述问题，产品定位从“论文写作工具”演进为“围绕论文项目持续推进的写作工作台”。详见：

## 3. 竞品调研与商业分析

调研将竞品分为三类：

| 类型 | 代表产品 | 优势 | 缺口 |
| --- | --- | --- | --- |
| 通用 AI | ChatGPT、DeepSeek、豆包等 | 生成能力强、成本低、使用灵活 | 没有论文项目结构、引用管理和学校格式约束 |
| 论文写作工具 | 秘塔写作猫、千笔论文、火龙果写作等 | 润色、降重、论文模板能力较强 | 付费门槛高，流程割裂，合规信任不足 |
| 文献管理工具 | Zotero、EndNote、Mendeley 等 | 文献管理专业 | 学习成本高，不覆盖选题、写作和计划 |

PaperPilot 的差异化机会在于：

- 将研究设计、写作和文献库真正串联。
- 用 GB/T 7714 和模板预览解决中文论文格式问题。
- 把“计划与打卡”作为论文周期管理能力，而不是附属小功能。
- 保持 BYOK 与本地数据架构，降低课程展示和个人试用门槛。

商业化层面，当前版本适合免费内测和课程展示。若后续正式商业化，需要补充账号、云同步、额度计量、托管模型调用和学校/导师协作能力。

## 4. PRD 与功能范围

最终版本围绕六个主模块组织：

| 模块 | 核心能力 |
| --- | --- |
| 论文主页 | 项目状态、下一步入口、写作进度、继续写作 |
| 研究设计 | 定题、方案收敛、研究问题/方法/数据/范围选择、大纲生成 |
| 论文写作 | 结构化编辑器、章节目录、AI 初稿、润色、补论证、重构、续写、逻辑检查 |
| 文献与证据 | 智能检索、文献库、GB/T 7714、正文引用同步、证据卡 |
| 计划与进度 | 可选截止日期、时间轴、今日任务、打卡记录 |
| 设置 | API Key、真实调用开关、演示数据、本地数据备份 |

功能边界：

- 支持章节级初稿与写作建议，但不做整篇代写。
- 支持引用整理和格式导出，但不伪造文献或数据。
- 支持本地备份，但当前不提供账号和云同步。

## 5. 视觉稿与交互设计

项目采用“纸墨朱砂”的视觉方向：

- 纸色背景用于承载论文写作场景。
- 墨蓝用于主操作与导航。
- 朱砂用于 AI 动作、批注、警示和重点标记。
- 松烟绿用于完成态与成功状态。
- 写作区模拟论文稿纸，提升沉浸感和论文工具辨识度。

交互设计经历了多轮重构。早期页面偏表单和卡片堆叠，后续逐步改为：

- 研究设计采用问卷式流程，用户通过选择而不是大量输入推进。
- 写作工作台以编辑器为中心，AI 工具直接作用于正文。
- 文献与证据拆成“找文献、管文献、做证据卡”的流程。
- 导出、格式整理、引用整理等工具集中到写作台。
- 截止日期和打卡从主流程强制项降级为可选计划能力。

## 6. 技术方案

### 6.1 技术架构

项目采用前端单页应用架构：

- Vite 负责开发服务器和生产构建。
- 原生 JavaScript 模块组织业务逻辑。
- ProseMirror 承载结构化富文本编辑器。
- localStorage / IndexedDB 保存项目、正文、文献、版本和设置。
- 大模型 API 采用 OpenAI 兼容协议，默认面向 DeepSeek，也可配置其他兼容服务商。
- GitHub Pages 承载线上版本。

### 6.2 关键模块

| 文件 | 作用 |
| --- | --- |
| `js/app.js` | 应用入口、模块注册、导航与全局状态 |
| `js/modules/topic.js` | 研究设计与大纲流程 |
| `js/modules/writing.js` | 写作工作台、编辑器、AI 写作工具、预览与导出入口 |
| `js/modules/citation.js` | 文献检索、文献库、证据卡 |
| `js/modules/planner.js` | 计划、任务和打卡 |
| `js/api.js` | AI 调用、演示模式、错误处理 |
| `js/docx-export.js` | Word 导出版式 |
| `js/document-model.js` | 论文结构化文档模型 |
| `js/project-db.js` | 多项目数据管理 |

### 6.3 部署方案

GitHub Pages 使用 Actions workflow 发布：

- 推送到 `main` 后触发 `.github/workflows/pages.yml`。
- workflow 执行 `npm ci` 与 `npm run build`。
- 将 `dist/` 作为 Pages artifact 发布。
- Vite 配置 `base: './'`，解决 GitHub Pages 子路径 `/paper-pilot/` 下 CSS/JS 资源加载问题。

## 10. 后续改进方向

Beta 阶段后建议优先处理：

- 拆分 JS bundle，降低首屏资源体积。
- 增加账号和可选云同步能力。
- 增强 Word/PDF 导出的学校模板可配置性。
- 引入 Zotero / BibTeX / EndNote 等文献生态导入导出。
- 增加面向导师或学校的合规说明导出。
- 建立真实用户反馈收集机制。
