# PaperPilot 项目复盘

## 1. 原计划做什么

项目最初目标是做一个论文写作辅助系统，帮助用户从选题、研究设计、文献整理、章节写作、进度管理到导出提交形成完整链路。重点不是单点 AI 问答，而是把论文写作拆成可操作、可回溯、可逐步确认的工作流程。

## 2. 实际完成了什么

- 建立了多项目、本地持久化和备份恢复能力。
- 完成研究设计问卷流，支持题目候选、研究方案、范围收敛和大纲生成。
- 重构写作台，支持章节目录、富文本编辑、图片、表格、公式、注释、引用和 AI 辅助工具。
- 完成文献与证据页，支持智能检索、文献库、证据卡和引用同步。
- 优化论文主页、计划页、设置页和整体视觉系统。
- 支持 Word、PDF、Markdown 导出和模板预览。
- 补充数据安全、提示词注入防护、AI 使用声明和测试文档。
- 完成 GitHub Pages 上线和交付文档页。

## 3. 为什么有差异

项目中后期发现，单纯堆功能会导致页面复杂、流程断裂和卡片混乱。因此迭代重点从“把功能做出来”转向“把流程串顺、把核心入口收拢、把用户选择成本降低”。此外，真实 AI 调用存在耗时、格式不稳定、引用同步和伦理披露问题，后续又补充了错误提示、流式输出、提示词防护和 AI 使用留痕。

## 4. 以后怎么改进

- 更早建立端到端测试脚本，减少手工验收成本。
- 在 PRD 阶段就明确“哪些功能是主流程，哪些是辅助功能”，避免页面越做越重。
- 将学校模板差异做成配置化模板，而不是在通用模板中硬编码。
- 增加正式外部同行评审记录，让产品评审更客观。
- 对 AI 输出建立更严格的结构化校验和失败恢复策略。

## 5. 个人收获

本项目的关键收获是：AI 产品的难点不只是模型调用，而是把模型输出放进一个可靠、可解释、可编辑、可追溯的用户流程里。论文写作场景尤其需要边界感，系统必须既能提高效率，也要提醒用户保留主体责任和学术规范。
