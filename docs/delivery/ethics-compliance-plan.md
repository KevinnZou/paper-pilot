# PaperPilot 学术伦理与合规说明

## 1. 合规定位

PaperPilot 的定位是“论文写作辅助系统”，不是论文代写系统。系统提供选题梳理、结构建议、文献检索辅助、局部草稿、语言润色、论证补充、格式整理和导出能力；用户仍需对研究思路、数据真实性、引用准确性、最终表达和学校规范负责。

系统采用三层合规思路：

- 法律层：关注学位论文真实性、署名责任、数据安全和 AI 生成内容标识要求。
- 学校层：不同学校对 AI 辅助写作的边界不同，系统只提供通用提示和留痕能力，最终以用户所在学校规定为准。
- 期刊与学术共同体层：AI 不能作为作者，AI 参与应在需要时披露，引用和事实必须可追溯。

## 2. 伦理检查清单

| 检查项 | 当前状态 | 处理方式 |
| --- | --- | --- |
| 是否提供“一键生成整篇论文” | 否 | 系统按章节和局部任务生成，不提供整篇论文一键代写入口 |
| 是否代替用户确定核心创新和结论 | 否 | 研究设计采用问卷式选择，用户确认题目、问题、方法、数据和范围后才进入大纲 |
| 是否生成或伪造实验数据 | 否 | 不提供数据伪造功能，AI 文案中强调数据需用户核验 |
| 是否可能未规范引用他人成果 | 已控制 | 初稿生成会检索文献并插入引用，文献可进入文献库，导出前检查会检查引用问题 |
| 是否限制长篇生成 | 已控制 | 初稿按当前章节或小节生成，避免一次性生成整篇论文 |
| 是否把“降重”作为核心卖点 | 否 | 文案使用“学术润色、重构表达”等写作辅助措辞，不以规避查重为目标 |
| 是否提供 AI 使用留痕和声明 | 已完成 | 项目设置页展示 AI 使用记录；导出 Word/PDF/Markdown 时附 AI 辅助使用声明 |
| 是否提供可追溯依据 | 已完成 | 文献库、证据卡、引用编号、版本记录、开发日志和交付文档共同支持追溯 |

## 3. 产品内已实现的合规机制

- 本地数据优先：论文、文献、证据、版本和 API Key 默认保存在浏览器本地。
- API Key 驱动：未配置 Key 时 AI 功能提示配置；保存 Key 后自动使用用户配置的模型服务。
- 提示词注入防护：系统通过 `safeSystemPrompt`、`hardenMessages`、`untrustedBlock` 区分系统指令与用户/文献等不可信内容。
- 输出显式声明：导出和复制全文时自动加入“AI 辅助使用声明”。
- 使用留痕：研究设计、生成大纲、写作台 AI 工具和生成初稿会记录到项目 AI 使用记录中。
- 人工确认：AI 建议需要用户接受才写回正文，逻辑检查以报告/待办形式呈现。

## 4. 用户侧注意事项

用户在正式提交论文前，应确认：

1. 学校是否允许使用 AI 辅助写作，以及是否要求在论文中披露。
2. 所有 AI 生成内容是否经过本人审阅、修改和事实核验。
3. 正文引用是否与文献库条目一致，参考文献格式是否符合学校要求。
4. 数据、图表、访谈材料和案例材料是否真实、合法、可说明来源。
