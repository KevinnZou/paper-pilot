## 1. 产品概述

### 1.1 背景与动机（调研数据支撑）

论文写作是高校学生的核心学业任务，调研发现六大痛点：

1. **查重 + AIGC 率双重焦虑（高频/高强度）**：高校普遍要求双达标（20%–30%，个别 5%），AI 检测不可靠（同一论文跨平台结果可差 20+ 个百分点），认真原创的学生也被迫焦虑
2. **拖延与周期失控（高频）**：论文周期数月、缺乏计划与外部监督；在职学生时间碎片化，非全硕士按期毕业率仅约 50%
3. **选题与开题迷茫（高频）**：选题反复更换、可行性无从判断、大纲不会搭
4. **文献综述耗时（高频）**：文献多而杂，综述无从下手
5. **参考文献格式繁琐（中频）**：GB/T 7714 手工排版耗时易错；通用 AI 不支持国标，专业工具重、付费、需配置
6. **表达与润色（中频）**：口语化、冗长、学术表达不规范

同时市场已具备产品土壤：高等教育在学 4872.57 万人（教育部 2025 统计公报），大学生 AI 使用率 94%–99%，首选免费国产模型（DeepSeek 72.1%）；但现有工具要么是"无场景的通用 AI"，要么是"单点功能 + 付费墙的论文工具"——**缺少一个覆盖全流程、免费、合规导向的轻量助手**。

### 1.2 产品定位（G0 评审通过）

**覆盖论文全流程、唯一内置写作计划管理、国标引用合规的轻量助手。**

三条产品原则：

1. **全流程而非单点**——选题 → 写作 → 文献 → 进度一条链
2. **计划管理作为记忆点**——利用全行业空白，做"能陪你写完论文"的工具
3. **合规优先**——在 AI 与学术诚信的敏感地带做正确的事，成为信任资产

### 1.3 产品目标

1. 降低论文启动与定框架的时间成本（选题+大纲从数天缩短到分钟级）
2. 写作过程中即时获得学术化润色与摘要辅助
3. 参考文献格式一键生成，消除手工排版负担
4. 用计划与打卡机制对抗拖延（全行业空白的能力）
5. 零成本使用：无需服务器、用户自带 Key，浏览器打开即用
6. 合规安心：全程学术诚信引导，用户敢用、用得起

### 1.4 成功指标（课程验收标准）

- 四大功能模块均可真实使用（AI 功能真实调用大模型 API）
- 无后端部署：GitHub Pages / Netlify 纯静态托管，演示零失败
- 用户可在 1 分钟内从打开页面到产出第一条 AI 结果
- 所有 AI 输出场景均有学术诚信提示（合规立场落地）

## 2. 市场与用户洞察（调研摘要）

> 完整数据与来源见 docs/analysis/market-and-competitor-analysis.md、docs/analysis/user-research.md。

### 2.1 竞争格局与差异化机会

- **三派玩家**：通用 AI（免费强但无场景、无国标、无计划）｜论文 AI 工具（单点功能、付费墙、口碑一般）｜文献管理（专业但重、国标需配置）
- **三个空白点**：① 写作计划管理（全行业空白）② 轻量国标引用方案 ③ 合规引导定位
- 国外趋势借鉴：合规能力（Paperpal、Grammarly EDU 的 Authorship 追踪）正在成为护城河；免费策略用"按量配额"而非功能阉割——BYOK 天然是按量

### 2.2 用户画像（3 类）

| 画像 | 特征 | 核心痛点 | 产品启示 |
|---|---|---|---|
| 小李 · 本科应届 | 选题换三次、催开题 | 选题可行性、大纲、格式 | 输入门槛低；格式"复制即用" |
| 王姐 · 在职 MEM | 时间碎片、常断更 | 拖延、进度失控 | **计划管理是第一需求入口** |
| 陈同学 · 研究生 | 投稿 + 学位论文并行 | 引用闭环、合规焦虑 | 写作中产出规范引用；诚信提示是加分项 |

### 2.3 使用行为分层与产品边界

| 层级 | 行为 | 产品态度 |
|---|---|---|
| 安全区 | 检索、翻译、润色 | 完整支持 |
| 灰色区 | 章节初稿生成、续写、降重改写 | 支持 + 合规引导（初稿基于用户大纲/要点生成、须亲自审阅修改；保留原意、自行核实、勿规避检测） |
| 越界区 | 整篇代写、伪造数据 | **明确不做（Won't）** |

### 3.2 功能清单与优先级（MoSCoW · G1 评审通过）

**Must（16 项）**：选题建议、大纲生成、摘要生成、学术润色、段落扩写、降重改写（合规导向）、**章节初稿生成（基于大纲+要点，人工审阅后修改）**、GB/T 7714 格式化、AI 文献解析、**在线文献查找（CrossRef 真实数据库，选题/章节语境推荐，人工勾选审核入库）**、计划模板+甘特图+倒计时、每日打卡、API 设置与连接测试、学术诚信提示、仪表盘（论文主页）、**论文项目主线与模块衔接（§4.4）**

**Should（3 项）**：文献库完整增删改查、结果复制/导出 Markdown、写作提示词模板库

**Could（2 项）**：打印/导出 Word 样式、写作统计图表

**Won't（3 项，红线）**：整篇代写、AIGC 检测集成、账号系统/云端同步

## 4. 产品架构

### 4.1 信息架构

```
PaperPilot
├── 仪表盘（进度总览 / 倒计时 / 快捷入口）
├── 选题与大纲（选题建议 / 大纲生成）
├── 写作辅助（摘要 / 润色 / 扩写 / 降重改写）
├── 文献与格式（文献库 / 格式化 / AI解析）
├── 计划与进度（计划模板 / 甘特图 / 打卡）
├── 设置（API配置 / 数据管理）
└── 全局：学术诚信提示（AI输出场景）+ 页脚诚信声明
```

### 4.2 核心交互流程

以"生成选题建议"为例：输入方向词 → 点击生成 → 前端校验（Key 已配置？输入非空？）→ 调用大模型 API（加载态）→ 成功：渲染结果卡片（可复制/采用）+ 学术诚信提示条 → 失败：按错误码给出可行动提示（如"Key 无效，请到设置中检查"）。

### 4.3 页面原型

- 左侧固定导航 + 主内容区，单页切换无刷新
- 每个功能 = 「输入卡片 + 操作按钮 + 结果区 + 诚信提示」四段式布局
- **写作工作台（v2.4）**：以「大文本框文档编辑器」为核心——支持「✨ 生成初稿」（基于论文题目+大纲+用户要点生成本章草稿，写入编辑器后用户逐段审阅修改，编辑器已有内容时需确认覆盖）、AI 动作（润色/扩写/降重/续写作用于选中文字，结果替换或插入到文档中，可 Ctrl+Z 撤销）、自动保存/实时字数/首次动笔自动标记"进行中"；摘要生成为"基于已写草稿"的右侧工具（初稿成型后使用）；左栏章节导航（显示各章字数）、右栏文献插入+素材库，全程不离开编辑器（v2.8 起右栏精简为「插入引用/摘要/素材」三件套，查找文献统一去文献中心）

**完整论文文档（v2.9）**：工作台 = 一份连续完整的论文文档（论文题目、摘要、关键词、各章、参考文献、致谢），左栏目录点击**定位**到对应位置（不重建编辑器、光标不丢）；保存时按标题行解析同步回章节结构与摘要等字段。

**规范引用（v2.9）**：正文中只插入**引用序号 [n]**（光标处），完整条目不写入正文——「复制全文 / 排版预览」时按文献库稳定编号（litNo，入库时分配、永久绑定）在文末参考文献区自动列出；排版预览生成打印级 HTML（宋体正文、首行缩进、居中标题），可打印/另存 PDF。
- 选题建议解析为卡片列表，每条可一键「设为论文题目」；论文主页每章有「去写」直达入口与「继续写作」主按钮
- **写作之旅流程条（v2.10）**：论文主页顶部五步引导（填 Key → 定题 → 采大纲 → 设截止 → 开始写），完成自动打勾、点击任意步骤直达；主行动按钮始终指向"下一步"
- **演示数据（v2.10）**：设置页「🧪 载入演示数据」一键填充示例论文（题目/大纲/草稿/文献/打卡），用于课堂演示与快速体验；工作台工具栏分组（初稿｜AI 动作｜导出）、目录定位闪烁反馈、摘要支持本章/全文两口径、甘特图标记"今天"与当前阶段、文献入库后引导"去工作台插入引用"
- 全部操作实时反馈（加载态 / 成功 / 错误 toast）

### 4.4 模块衔接设计（G3 评审新增 · 论文项目主线）

**背景**：G3 原型评审反馈——各模块功能可用但彼此割裂，与「全流程」定位存在落差。解决方案：引入贯穿全局的「论文项目」主线，四个模块读写同一份项目数据。

**数据模型（localStorage: paperpilot:project）**

| 字段 | 内容 | 写入方 |
|---|---|---|
| title / degreeType / dueDate | 论文题目、学位类型、截止日期 | 设置、仪表盘、选题模块 |
| outline | 采用的大纲章节列表 | 选题与大纲（「采用此大纲」） |
| chapterProgress | 各章进度（未开始/进行中/已完成） | 打卡、写作辅助 |
| stages | 写作计划阶段 | 计划与进度（与甘特图同步） |
| materials | 写作素材（摘要/段落草稿） | 写作辅助 |

**四条衔接链路**

1. **大纲 → 计划**：生成大纲后「采用此大纲」→ 章节成为写作任务目录，与计划甘特图关联
2. **文献 → 写作**：文献库条目可在写作辅助中「插入引用」，直接插入 GB/T 7714 格式（Sprint 2 落地 UI）
3. **打卡 → 仪表盘**：打卡时选择「今天写了哪一章」→ 论文主页显示各章进度条与连续打卡天数
4. **项目 → 全局**：所有模块预填论文题目；顶部展示当前论文；仪表盘重构为「论文主页」聚合视图
5. **章节 → 写作（v2.2）**：写作工作台按大纲章节导航，写作上下文始终关联当前章节；「标记本章完成」同步论文主页
6. **结果 → 素材库（v2.2）**：AI 生成结果可一键「保存为素材」（含章节标签），素材库沉淀摘要与段落草稿，可复制/删除

7. **选题/章节 → 文献查找（v2.7）**：确定选题后或写作时，按语境在真实学术数据库（CrossRef/OpenAlex 自动切换）检索推荐文献。流程分三段——① **AI 检索策略**：把论文题目与各章转化为英文学术检索词（解决中文语境对英文数据库的匹配难题，最多 8 组）；② **真实检索+合并去重**：并行检索、按 DOI/题名跨组去重；③ **AI 推荐理由标注**：为每条候选标注"可印证/支撑论文的哪个点"（如支撑方法设计/对比 baseline/综述素材）并匹配最适配章节，按章节分组展示。候选条目可展开详情、点「🔗 原文」核对；已在库中自动标记并去重——用真实元数据杜绝 AI 幻觉引用（对应调研发现的"引用真实性"空白）。

**双语检索（v2.8）**：国际库以英文文献为主，新增 OpenAlex 中文文献通道（`language:zh`，覆盖部分中文学术期刊）；批量推荐与含中文的单次检索并行检索中英两组，结果按「🇨🇳 中文文献 / 🌐 英文文献」分组，中文排前。知网等中文库无开放 API——缺口通过「AI 解析」（粘贴知网条目）补充。

**功能重分布（v2.8，按"收集→使用"划分）**：文献与格式模块 = 文献中心，负责全部收集与审核（智能推荐与检索置顶为主入口，AI 解析/手动录入为辅助，文献库为管理区）；写作工作台右栏精简为写作场景三件套（插入引用 / 生成摘要 / 素材库），查找文献移至文献中心入口按钮。

**实施划分**：Sprint 1 = 项目状态管理 + 论文主页 + 链路 ①③；Sprint 2 = 链路 ②④ 的 UI 接入；v2.2 打磨 = 写作工作台（链路 ⑤⑥）、选题「设为论文题目」、主页章节直写入口；v2.5 = 链路⑦ 在线文献查找。

## 5. 技术方案

### 5.1 总体架构

**纯静态前端应用（无后端）**，托管于 GitHub Pages / Netlify。浏览器直连 DeepSeek（OpenAI 兼容协议），Key 仅存本地 localStorage。

### 5.2 技术选型与理由（同 v1，调研后无变化）

| 选择 | 理由 |
|---|---|
| 原生 HTML/CSS/JS（ES Modules） | 无构建链、零依赖、演示稳定；维护性第一 |
| localStorage | 无需后端数据库，Key / 文献 / 计划数据本地持久化 |
| OpenAI 兼容 API 协议 | DeepSeek、OpenAI、Moonshot 等任意服务商可切换 |

### 5.3 API 集成设计（同 v1）

- 端点：`{baseURL}/chat/completions`（默认 `https://api.deepseek.com`）
- 模型：默认 `deepseek-chat`，可在设置中修改
- 认证：`Authorization: Bearer {apiKey}`，Key 由用户自行填入，仅存本地
- 请求：非流式（`stream:false`）+ 温度按场景（选题 0.8 / 润色 0.3）
- 错误映射：401→Key无效、402→余额不足、429→限流、网络错误→连接失败

### 5.4 提示词工程（v2 新增合规约束）

- 系统提示词：学术导师角色 + **合规约束**（"不代替用户完成整篇论文（整篇代写）；基于用户提供的大纲、要点撰写章节草稿属于允许的辅助，但须提醒用户亲自审阅、补充个人观点与数据；改写需保留原意并提醒用户自行核实"）
- 降重改写提示词加入合规使用说明，输出附诚信提示
- 文献推荐双 AI 环节：检索策略生成（中文语境→英文学术检索词）+ 推荐理由标注（每条候选标注"可印证/支撑哪个点"并匹配章节）；JSON 输出解析做容错（容忍代码围栏与包装对象）
- 输出要求：直接给正文结果、避免客套话

### 5.5 学术诚信提示实现

- 前端静态文案，不依赖 AI：结果区提示条（写作辅助/选题大纲的 AI 输出下方）+ 页脚全局声明
- 文案：「AI 生成内容仅供参考，观点与数据请自行核实，并遵守所在学校的学术规范」

### 5.6 数据设计（localStorage 键值表，同 v1）

| Key | 内容 |
|---|---|
| `paperpilot:config` | apiKey / baseURL / model |
| `paperpilot:citations` | 文献条目数组 |
| `paperpilot:plan` | 计划阶段、关键日期 |
| `paperpilot:checkins` | 打卡记录 |

### 5.7 安全与隐私（同 v1）

- API Key 仅存浏览器本地，不写入代码库、不上传任何服务器
- 页面内提供「数据说明」，告知用户所有数据保存在本地
- 代码仓库中不出现真实 Key（.gitignore + 敏感信息检查）

- 兼容：Chrome / Edge / Safari 近两年版本
- 响应式：桌面优先，窄屏下导航折叠
- 性能：首屏静态资源 < 500KB，无外部依赖
- 可用性：所有错误有可行动的中文提示；无网络时可演示规则类功能（文献格式、计划、打卡）
- 视觉：统一「纸墨朱砂」设计语言（v3.0）——纸色底+宋体标题+等宽数字；语义色系统：墨蓝=用户动作、朱砂=AI 动作与批注、松烟绿=完成态（印章标记）；编辑器为稿纸式纸页；符合 WCAG 可见焦点与 reduced-motion

| CrossRef/OpenAlex 外部 API 不可用 | 低 | 中 | 双数据源自动切换（CrossRef 主源、OpenAlex 备源，均已实测浏览器跨域可用）；失败时明确报错提示重试，手动录入与 AI 解析两条路径兜底 |
