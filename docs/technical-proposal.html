01项目概述

1.1背景与目标

PaperPilot 是一款面向学位论文/课程论文写作的 AI 辅助工具，覆盖「选题 → 框架 → 写作 → 文献 → 计划 → 交付」全流程。当前产品已实现核心功能并进入演示与验收阶段，本方案在现有代码基线上给出可评审的技术路线：以零后端、BYOK（Bring Your Own Key，用户自带密钥）纯前端架构为主干线，并给出演进路径、压力测试、容灾与部署方案。

产品目标（KR 对齐）：

  • 写作提效：选中文字即可润色/扩写/降重/续写，AI 就地替换、可撤销重做；
  • 文献可信：CrossRef / OpenAlex 真实学术数据库检索，AI 生成检索策略与推荐理由，一键入库并自动生成 GB/T 7714-2015 参考文献；
  • 过程可控：章节字数实时统计、截止日期甘特图倒排、每日打卡热力图；
  • 数据自主：全部数据存于用户本机浏览器，可导出/导入备份，无账号体系、无数据采集。

1.2范围

范围内（In Scope）范围外（Out of Scope）
  • 论文选题推荐、研究框架生成、写作工作台（AI 动作 + 引用插入）
  • 学术文献检索（CrossRef/OpenAlex）、AI 标注、GB/T 7714 引用格式化
  • 甘特图 / 打卡 / 热力图计划模块，排版预览与导出
  • 本地数据备份 / 恢复 / 迁移，多服务商 AI 接入
  • 任何形式的账号、登录、云端同步（数据上云）
  • AI 服务端代理 / 密钥托管 / 计费网关
  • 整篇论文自动代写（仅逐段辅助）
  • AIGC 生成内容检测（合规红线，不集成）
  • 知网等无开放 API 的中文库直连（以 AI 解析粘贴兜底）

2.3现状差距（本方案要解决）

  1. 无自动化发布流水线：目前仅本地 git，无 CI/CD、无托管环境、无域名与 HTTPS 规划；
  2. 压力测试空白：AI 并发、检索限流、localStorage 容量边界、大文档渲染均无量化验证数据；
  3. 容灾手段单一：仅有手动导出/导入备份，缺自动提醒、损坏自愈与演练流程；
  4. 监控缺失：无前端错误采集、无外部服务可用性监测；
  5. 存储演进预案：localStorage 5 MB 上限对长论文存在理论瓶颈，需给出 IndexedDB 演进预案。

03总体架构

3.1架构形态：浏览器单机 + 外部 API 直连（无自有后端）

核心决策：产品不建设自有后端。所有计算在浏览器完成，外部服务仅有三类只读/生成式 API（大模型、学术数据库、DOI 解析），全部由浏览器 HTTPS 直连。该形态由合规红线（BYOK 密钥不落服务器）与数据自主定位共同决定，也是本方案所有设计（容灾、监控、压测）的前提。

图 1 · PaperPilot 总体架构（浏览器单机 + 外部 API 直连）

3.2关键数据流

3.2.1 AI 动作（写作工作台）

选中文字 ──▶ 模块层拼接 messages（角色:系统/用户）
      ──▶ api.js：读取 config → POST {baseURL}/chat/completions（Bearer Key · 180s 超时 · AbortSignal）
      ──▶ 成功：返回文本 → 就地替换（可撤销/重做，Ctrl+Z 等效）
      ──▶ 失败：ApiError 分类提示（auth / rate / timeout / network / balance …）

3.2.2 文献检索（批量推荐）

题目+大纲 ──▶ AI 生成英文检索词（≤8 组 JSON）
      ──▶ 并行检索 CrossRef / OpenAlex（失败自动切换）+ 中文通道 OpenAlex language:zh
      ──▶ 按 DOI/题名去重合并 → AI 为 ≤20 条候选标注「可印证/支撑哪个点」
      ──▶ 人工勾选 → 入库（自动编号 litNo）→ gbt7714.js 生成引用 → 正文插入 [n]

3.2.3 密钥流动（BYOK 合规链）

用户填写 ──▶ localStorage['paperpilot:config']（同源私有，绝不上传）
      ──▶ 请求时读取 → Authorization 头 → 直达服务商（CORS 需服务商允许）
      ──▶ 导出备份时随文件本地下载（界面已提示妥善保管）
      ──▶ 任何中间服务器 / 监控 / 日志 均不接触 Key
合规红线（逐字执行） API Key 仅存在于浏览器 localStorage，绝不出现在代码库或上传（BYOK）；不写完整论文（定位逐段辅助）；不集成 AIGC 检测。所有技术方案（含监控、容灾、压测）不得突破上述三条。

3.3演进架构（评审预留）

保持主干线不动的前提下，预留两条演进路径（见 4.4 决策点 D1/D2）：

  • 存储演进：localStorage → IndexedDB（Dexie 封装），适配 >5 MB 长文档；
  • 可选代理层（不推荐）：若未来需要统计分析/多端同步，可引入无状态代理，但 BYOK 合规要求 Key 仍留浏览器，代理仅转发流式文本（需重新评审合规与成本）。

04技术选型

选型原则：零依赖优先、可审计优先、合规优先——面向「纯静态 + BYOK」定位，任何引入都必须问「能否删掉」。

维度候选方案结论决策理由
前端框架 React 19 / Vue 3 / Svelte 5 / 原生 ES Modules 原生 ES Modules 6 个模块页均为中小型表单/列表交互，无复杂状态共享；零依赖带来零供应链风险、零构建、零升级成本，页面首屏无需框架引导。框架引入时机见 D1。
构建工具 无构建 / Vite / esbuild 无构建 源码即产物，浏览器直接运行 ES Module；便于技术评审逐行审计（合规场景的重要资产）。演进时以 Vite 起步（零配置、快），见 D1。
本地存储 localStorage / IndexedDB（Dexie）/ 后端数据库 localStorage 容量测算：5 万字论文全文 ≈ 1.5 MB，1 000 条文献 ≈ 0.5 MB，合计 < 3 MB，5 MB 限额内（测算见 8.3）。同步 API 简单可靠，且已被 wrap 在 storage.js 单一入口，演进可替换。IndexedDB 演进预案见 10.5。
图表渲染 自研 SVG / ECharts / Canvas 自研 SVG 甘特图与打卡热力图形态固定、交互简单，自研 SVG 代码量小、风格与设计语言一致；ECharts 作为能力演进选项（热力图/走势图扩展时），见 D1 附注。
AI 接入 OpenAI 兼容协议直连 / 自建代理 / 第三方网关 协议直连 兼容协议使 DeepSeek/OpenAI/Kimi/自定义 Base URL 一码通吃；自建代理或网关会把 Key 引到服务器，破坏 BYOK 红线。非流式接口降低实现与调试成本（流式作为演进项，见 D6）。
文献检索 CrossRef / OpenAlex / Semantic Scholar / 知网（无开放 API） CrossRef+OpenAlex 两者均为免 Key 开放接口、覆盖主流英文文献；双源自动降级已实现；中文文献以 OpenAlex language:zh + 「AI 解析粘贴」兜底。Semantic Scholar 列为备用源。
引用格式 自研 gbt7714.js / citeproc + CSL 自研 gbt7714.js 仅需输出 GB/T 7714-2015 一种样式，自研 ~200 行可控可审；citeproc+CSL 引入 500 KB+ 依赖换多格式能力，当前不划算。
测试 Playwright / Vitest + jsdom Playwright 本项目价值在端到端流程（AI 调用、检索、入库、备份恢复），Playwright 已在流程图校验中使用；单元测试以 Vitest 补充纯函数（gbt7714 格式化、错误映射、去重）。
部署托管 GitHub Pages / OSS+CDN / Vercel Pages → OSS+CDN 静态站点无服务器计算；GitHub Pages 起步零成本，正式环境演进至对象存储+CDN 双活（见第 11 章）。Vercel 作为备选（国内访问与合规因素列为风险 R6）。
监控 自研轻量上报 / Sentry 前端版 / 不监控 自研+可选 Sentry 无后端形态下监控必须满足「不上送任何用户数据与 Key」（脱敏后仅错误类型/URL/堆栈哈希）。默认自研 localStorage 日志 + 可选接入 Sentry（评审 D4）。
选型结论 维持「原生 ES Modules + 零依赖 + localStorage + 双源学术检索 + OpenAI 兼容多服务商」主干线；所有演进项（框架、构建、IndexedDB、流式、ECharts）均在既有封装边界内可替换，不影响当前交付。

5.2关键设计决策

5.2.1 切页中断（已实现）

所有长耗时操作（AI 生成、检索、标注）挂载于 tm:navigate 事件驱动的 AbortController；导航离开即 abort，避免结果写回已卸载页面、避免请求悬挂与按钮卡死。此模式是压测与容灾设计的基础。

5.2.2 错误即文案（已实现）

12 类 ApiError 全部映射为面向用户的可读文案（如 429 →「请求过于频繁，请稍等几秒再试」；401/403 →「API Key 无效」），且不误导归因（AI 检索策略失败时透传可读错误，不让用户误以为是 Key 问题）。

5.2.3 双源降级（已实现）

CrossRef 失败自动切换 OpenAlex，任意单一学术库不可用不影响检索主链路；中文检索走 OpenAlex language:zh，失败静默降级为英文结果。

5.2.4 防抖与自动保存（写作工作台）

章节草稿输入防抖落盘（避免高频 setItem），字数实时统计；结合 localStorage 同步 API 保证同标签页内数据一致性（跨标签页一致性限制见 10.2 风险 R3）。

07安全与合规设计

7.1密钥安全（BYOK）

风险面控制措施
Key 上传服务器架构上无后端；请求由浏览器直发服务商；发布物与仓库做敏感扫描（已纳入 CI，见 11.3）
Key 出现在日志/监控监控采集脱敏：请求/响应体不采集，仅错误类型 + 状态码 + 堆栈哈希；Sentry 接入时配置 scrubbing（见 D4）
备份文件泄露导出文件名含日期；界面文案「备份文件包含你的 API Key，请妥善保管、勿外传」
同源 XSS 窃取7.2 全量转义 + CSP；Key 以 password 输入框展示，可一键显示/隐藏
Key 进入 git 历史.gitignore 与 CI 敏感扫描（防误提交）；真机验收中 Key 由用户自填，开发环境不落盘

7.2Web 安全

  • XSS：用户数据渲染一律经 escapeHtml（唯一出口），外部数据（文献标题/作者/摘要）同样转义；外链 rel="noopener"、target=_blank 受控；
  • CSP 建议（上线时启用）：default-src 'self'; script-src 'self'; connect-src 'self' https://api.deepseek.com https://api.openai.com https://api.moonshot.cn https://api.crossref.org https://api.openalex.org https:; img-src 'self' data:; style-src 'self' 'unsafe-inline'——connect-src 与服务商白名单联动（用户自定义 Base URL 时需在设置中确认并动态放宽到该域名，见 D1 附注）；
  • 隐私：无账号、无埋点、无 Cookie 追踪；本地数据默认不外送；检索词仅发往学术数据库（用途即接口语义）。

7.3合规边界

三条红线（评审锚点）① 不写整篇论文——产品定位为逐段辅助（润色/扩写/降重/续写/文献/计划），交付物由用户主导；② 不集成 AIGC 检测；③ API Key 不落任何服务器。任何演进提案触碰红线即否决。

8.2API 调用策略

  • 超时：AI 180 s（生成长文）；连接测试 30 s；检索 30 s（fetch 默认无超时，由 AbortController 兜底）；
  • 中断：切页即 abort（已实现），避免悬挂与资源浪费；
  • 限速：学术库前端限速队列 ≤ 3 req/s（CrossRef 礼貌池安全余量），批量检索 8 组并发受队列约束；
  • 重试与退避：429/5xx 指数退避（1s→2s→4s，最多 2 次重试）——当前未全量实现，列为里程碑 M2 项（9.2 压测给出参数验证目标）；
  • 熔断：学术库单源连续失败自动切换对源（已实现）；AI 服务商无自动切换（密钥属用户，切换即用户设置），以可读错误 + 手动切换兜底。

9.3故障注入清单

  • 网络层：断网（离线提示）、弱网（4G 节流）、延迟抖动、DNS 失败；
  • 协议层：HTML 网关页冒充 JSON（bad_response 路径已实现，需回归）、空响应、截断响应；
  • 业务层：429/500/401/402/403、检索返回空、AI 返回非 JSON（容错解析已实现）；
  • 本地层：localStorage 不可用（隐私模式）、配额触顶、数据损坏（手改非法 JSON，验证 get() 回退默认值）。

9.4执行节奏

  • M2 阶段每周一次回归（P6）+ 每两周一轮全量（P1–P5）；
  • 发布前必须 P1/P3/P6 全绿 + P4 容量验证；
  • 压测脚本入仓 tests/stress/，随代码评审。

10.2跨标签页一致性（已知限制）

限制声明（评审已知项）localStorage 在多标签页间不同步：两个标签页同时写作时后写覆盖先写。缓解：文档中声明「建议单标签页使用」；M2 可选实现 storage 事件监听 + 冲突提示（改动面小，列为 D3 附注）。

10.3服务容灾（外部 API 依赖降级）

  • 学术库：CrossRef ↔ OpenAlex 双源自动切换（已实现）；中文通道失败静默降级；
  • AI 服务商：Key 属用户，故障时给出可读错误 + 设置页一键换服务商（配置 3 预设 + 自定义 URL）；
  • 离线：断网时检索/AI 明确报错且不破坏本地数据；本地功能（编辑、计划、打卡、导出）完全可用；
  • 超时兜底：180 s 上限 + AbortController，无悬挂请求。

10.4部署容灾

  • 静态资源不可变发布（目录带版本），回滚 = 切换上一版本目录 + CDN 缓存刷新；
  • 双环境隔离（预发布/生产），预发布验证通过才切生产；
  • CDN 多可用区 + 源站（OSS）双活；域名 HTTPS 全覆盖（见第 11 章）。

10.5存储演进预案（IndexedDB）

触发条件：单用户数据量持续逼近 5 MB（或评测要求多标签页一致）。方案：storage.js 为唯一入口，新增 IndexedDBStore 实现同接口（get/set/remove），读取顺序「IndexedDB 优先，缺省回落 localStorage 并迁移」；旧数据一次性迁移脚本 + 迁移前自动导出备份。由于全部读写已收敛于 storage.js，迁移不侵入业务模块（评估 3 人日）。

15技术评审决策点（请评审组确认）

D1 · 是否引入前端框架与构建工具（原生路线 vs Vite+React）

本方案推荐：继续原生 ES Modules 路线（评审期内），理由：规模小、零依赖可审计（合规资产）、无构建成本；演进触发条件：模块数 > 10、页面状态共享复杂度上升、或需要流式输出与虚拟列表等能力时，以 Vite 起步迁移（评估 2 周）。

D2 · 是否建设后端代理（多端同步 / 统计分析）

本方案推荐：不建设。任何后端代理都与 BYOK 红线冲突（Key 若留在浏览器则代理仅转发文本，收益低、成本高）。若评审要求同步能力，须单独立项并重评合规。

D3 · IndexedDB 迁移时机

推荐：当前不迁（容量测算余量 58%），触发条件（任一）：① 实际数据量 > 4 MB；② 多标签页一致性成为硬需求。触发后按 10.5 预案执行（3 人日）。

D4 · 前端监控方案（自研本地日志 vs Sentry）

推荐：先自研本地日志（默认）+ Sentry 前端版可选接入。接入前提：配置字段脱敏 scrub（Key、正文、检索词一律不采集）、错误上下文仅含错误码/状态/哈希。不接入也不影响 M1–M2 交付。

D5 · 正式域名与 CDN 预算确认

阶段 2 需要评审确认：域名持有方、CDN 服务商（国内合规要求）、HTTPS 证书策略、年度预算（估算：域名 ~100 元/年，CDN/OSS 按流量，演示期 < 500 元/年）。

D6 · 移动端与流式输出范围

推荐：移动端保持「可读可用」级别（当前已在适配），不做完整桌面体验；流式输出（SSE）列为 M3 演进项——收益：长文生成首字更快；成本：接口改造 + 中断语义复杂化，评审确认优先级。

评审输出物① 评审结论与 D1–D6 决策；② 压测报告（M2 末）；③ 安全评审确认（BYOK 链路 + CSP）；④ 部署方案确认（域名/CDN）。
